# Паспорт проекта «Конструктор торта»

## 1. Общие сведения

| Параметр | Значение |
|---|---|
| Название | «Конструктор торта» |
| Заказчик | Небольшая кондитерская |
| Тип продукта | Одностраничное веб-приложение для самостоятельного расчёта заказа |
| Статус | MVP, первый этап |
| Срок реализации | 8–10 часов |
| Платформа | Мобильный и десктопный браузер |
| Стек | HTML + CSS + JavaScript, данные в `localStorage` |
| Хостинг | Статический, без серверной части |
| Основные документы | `docs/PROJECT_PASSPORT.md`, `docs/TZ.md`, `AGENTS.md` |

## 2. Проблема

Покупатель не понимает, сколько будет стоить торт, пока не напишет кондитеру. Кондитер тратит время на повторяющиеся уточнения: вес, начинка, декор, дата, состав, цена.

В результате покупатель дольше принимает решение, а кондитер обрабатывает больше переписки, чем нужно.

## 3. Цель и задачи

**Цель:** дать покупателю самостоятельно собрать торт, сразу увидеть стоимость и получить готовый запрос на заказ.

**Задачи:**

1. Показать понятную форму с весом, начинкой, декором и датой.
2. Сразу пересчитывать стоимость при любом изменении параметров.
3. Показывать расшифровку суммы по пунктам.
4. Формировать готовую карточку заказа.
5. Дать возможность скопировать карточку одним нажатием.
6. Позволить кондитеру менять цены и ограничения в одном файле настроек.

## 4. Пользователи

| Роль | Потребность | Результат |
|---|---|---|
| Покупатель | Быстро узнать стоимость и оформить заказ без переписки | Видит цену и копирует готовую карточку |
| Кондитер | Получать заполненные заказы и управлять ценами | Меняет параметры в конфиге, получает структурированный запрос |

## 5. Главный сценарий

1. Покупатель открывает калькулятор с телефона.
2. Выбирает вес торта.
3. Выбирает начинку и декор.
4. При необходимости добавляет надпись.
5. Выбирает дату и время выдачи.
6. Указывает имя и контакт для связи.
7. Видит расшифровку суммы и итоговую стоимость.
8. Нажимает «Сформировать заказ».
9. Проверяет карточку и нажимает «Копировать».
10. Вставляет карточку в чат с кондитером.

## 6. Результат проекта

- Покупатель получает прозрачную стоимость и готовый запрос на заказ.
- Кондитер получает полностью заполненную карточку без долгой переписки.
- Цены и правила расчёта хранятся в одном файле и легко меняются.

## 7. Границы MVP

### Входит в MVP

- Форма с весом, начинкой, декором, надписью и датой.
- Живой пересчёт стоимости.
- Автоматическая скидка за ранний заказ.
- Расшифровка суммы по пунктам.
- Проверка веса, даты, времени и обязательных полей.
- Карточка готового заказа.
- Копирование карточки одним нажатием.
- Сохранение черновика и последнего заказа в `localStorage`.
- Каталог начинок с локальными заглушками.
- Каталог декора с локальными примерами.
- Экран «Цены» для покупателя.
- Файл настроек `js/config.js` для кондитера.

### Не входит в MVP

- Онлайн-оплата.
- Расчёт и оформление доставки.
- Личный кабинет и авторизация.
- Админ-панель с редактированием цен через интерфейс.
- История всех заказов и статусы выполнения.
- Проверка занятости дат и производственных мощностей.
- Несколько тортов в одном заказе.
- Промокоды и программа лояльности.
- Ручные скидки, не связанные с датой выдачи.
- Фотографии начинок и другие внешние изображения: только локальные заглушки.
- Автоматическая отправка заказа в мессенджер или на почту.

## 8. Параметры продукта

| Параметр | Значение |
|---|---|
| Минимальный вес | 1 кг |
| Максимальный вес | 5 кг |
| Варианты веса | 1 / 1,5 / 2 / 2,5 / 3 / 3,5 / 4 / 4,5 / 5 кг |
| Цена начинки | За килограмм, от 2 500 ₽/кг |
| Декор | Фиксированная стоимость |
| Надпись | 300 ₽, до 30 символов |
| Скидка за ранний заказ | 5% от 7 дней, 10% от 14 дней |
| Минимальный срок заказа | 2 календарных дня |
| Горизонт заказа | 60 дней |
| Время выдачи | 10:00–19:00, шаг 30 минут |
| Способ получения | Самовывоз |
| Валюта | Рубли, целые числа |

Актуальные цены и описания хранятся в `js/config.js` и отображаются на экране «Цены».

## 9. Экраны

### 9.1. Калькулятор

Основной экран. Содержит форму, живой итог и кнопку «Сформировать заказ». На мобильном итог закреплён внизу экрана.

### 9.2. Карточка готового заказа

Появляется после успешной проверки формы. Содержит все параметры, контакт, расшифровку суммы и кнопку «Копировать». Карточку можно открыть повторно из сохранённого последнего заказа.

### 9.3. Каталоги начинок и декора

Открываются кнопками у блоков «Начинка» и «Декор». Каталог начинок показывает все начинки из конфига с локальной SVG-заглушкой, названием, ценой за кг и описанием. Каталог декора показывает пример для каждого варианта: без декора, минимализм, тематический, фигурки. Нажатие на карточку выбирает вариант и обновляет итог. Без внешних изображений и сетевых запросов.

### 9.4. Экран «Цены»

Показывает начинки с ценой за килограмм и описанием, декор с фиксированной ценой, минимальный вес, срок заказа и часы самовывоза. Данные берутся из конфига, экран только для чтения.

### 9.5. Настройки кондитера

Файл `js/config.js`. Кондитер меняет цены, описания, варианты веса, срок заказа и часы выдачи. После изменения файла страница перезагружается.

## 10. Данные

| Сущность | Поля |
|---|---|
| Начинка | `id`, название, цена за кг, описание, сюжет и цвета иллюстрации |
| Декор | `id`, название, фиксированная цена, описание, иллюстрация |
| Заказ | Параметры торта, сумма, скидка, дата и время, контакт, дата создания |

Заказ и черновик хранятся локально в браузере. Автоматической отправки данных на сервер нет.

## 11. Метрики успеха

- Покупатель видит стоимость менее чем за 60 секунд.
- Не менее 90% сформированных заказов содержат все обязательные поля.
- Расшифровка суммы всегда совпадает с итогом.
- Карточка копируется одним нажатием.
- Интерфейс удобен на экране шириной 375 px.
- Кондитер не тратит время на уточнение параметров, которые уже есть в карточке.

## 12. Ограничения и риски

| Риск | Как учитываем |
|---|---|
| Финальная стоимость может отличаться из-за сложности декора | В карточке указываем, что цена предварительная и кондитер подтверждает заказ |
| Нет проверки занятости даты | Покупатель выбирает желаемую дату, кондитер подтверждает возможность |
| `localStorage` может быть очищен | Черновик не является единственным источником данных; после копирования заказ уже у покупателя |
| Буфер обмена может быть недоступен | Добавляем запасной вариант копирования через текстовое поле |
| AI-сервис недоступен | Описание генерируется локально по шаблону; заказ можно оформить без AI |
| API-ключи нельзя хранить во фронтенде | AI-интеграция выполняется только через серверный прокси и не входит в базовый MVP |

## 13. Опционально: AI-описание

По желанию можно добавить генерацию красивого описания торта по выбранным параметрам через GigaChat или YandexGPT.

Правила:

- Модель не считает стоимость. Цену рассчитывает только код.
- Персональные данные покупателя в модель не передаются.
- API-ключи не попадают в клиентский код.
- При недоступности AI заказ всё равно формируется.
- Функция помечается как опциональная и не блокирует базовый MVP.

## 14. Сроки и этапы

| Этап | Ориентир |
|---|---|
| Паспорт, ТЗ и `AGENTS.md` | 1–1,5 часа |
| Вёрстка калькулятора | 2,5–3 часа |
| Логика расчёта и валидации | 2 часа |
| Карточка заказа и копирование | 1–1,5 часа |
| Проверка на телефоне и полировка | 1–2 часа |
| **Итого** | **8–10 часов** |

## 15. Критерии готовности

- [ ] Любое изменение параметров сразу пересчитывает сумму.
- [ ] Некорректный вес или прошедшая дата блокируют отправку с понятной подсказкой.
- [ ] Расшифровка суммы совпадает с итогом.
- [ ] Скидка за ранний заказ считается автоматически и попадает в карточку.
- [ ] Карточку заказа можно скопировать одним нажатием.
- [ ] На экране шириной 375 px всё читается и нажимается.
- [ ] Черновик восстанавливается после перезагрузки страницы.
- [ ] Каталог начинок открывается и выбирает начинку без сетевых запросов.
- [ ] Каталог декора показывает пример каждого варианта и выбирает декор.
- [ ] Экран «Цены» совпадает с данными конфига.
- [ ] Нет ошибок в консоли браузера.
- [ ] Заказ можно оформить с телефона без горизонтальной прокрутки.
- [ ] Кондитер может изменить цены и срок заказа в одном файле.
