# AGENTS.md

## 1. О документе

Этот файл описывает продукт, стек, правила разработки и интерфейса для «Конструктора торта». Его должны учитывать разработчики и ИИ-агенты при любых изменениях в проекте.

Источники истины:

- `docs/PROJECT_PASSPORT.md` — зачем нужен продукт и что входит в MVP.
- `docs/TZ.md` — подробные требования, расчёты, ограничения и критерии приёмки.
- `AGENTS.md` — практические правила реализации.

При противоречиях приоритет у `docs/TZ.md`, затем у `docs/PROJECT_PASSPORT.md`, затем у этого файла.

## 2. Назначение продукта

Небольшая кондитерская получает веб-калькулятор, в котором покупатель:

1. Выбирает вес, начинку, декор, надпись и дату.
2. Сразу видит стоимость и расшифровку.
3. Указывает имя и контакт.
4. Формирует карточку заказа.
5. Копирует карточку в мессенджер одним нажатием.

Главная ценность: покупатель не ждёт ответа кондитера, а кондитер получает заполненный запрос без повторяющихся уточнений.

## 3. Стек и ограничения

- HTML5.
- CSS3.
- Ванильный JavaScript.
- `localStorage` для черновика и последнего заказа.
- Статический хостинг.
- Без фреймворков.
- Без сборки и пакетного менеджера.
- Без серверной части в базовом MVP.
- Без внешних библиотек, шрифтов и тяжёлых изображений.
- Интерфейс на русском языке.

Базовый сценарий должен работать после загрузки страницы без сети.

## 6. Бизнес-инварианты

- Минимальный вес: 1 кг.
- Максимальный вес: 5 кг.
- Варианты веса: 1 / 1,5 / 2 / 2,5 / 3 / 3,5 / 4 / 4,5 / 5 кг.
- Минимальный срок заказа: 2 календарных дня.
- Горизонт заказа: 60 календарных дней.
- Время самовывоза: 10:00–19:00, шаг 30 минут.
- Надпись: до 30 символов, 300 ₽.
- Цены начинок — за килограмм.
- Цена декора — фиксированная.
- Скидка за ранний заказ: 5% при выдаче через 7–13 дней, 10% — через 14 и более дней.
- Итог — целое число рублей.
- Расшифровка суммы всегда равна итогу.
- Цена не зависит от имени, контакта и комментария.
- AI никогда не считает цену.

## 7. Правила расчёта

Формула:

```text
cake = weightKg × filling.pricePerKg
decor = decor.price
inscription = config.inscription.enabled && inscription.trim()
  ? config.inscription.price
  : 0
base = cake + decor + inscription
discount = -round(base × discountPercent / 100)
total = cake + decor + inscription + discount
```

Требования:

- Все денежные значения — целые рубли.
- `pricePerKg` задаётся кратным 50 ₽.
- Вес задаётся шагом 0,5 кг.
- Каждая строка округляется через `Math.round`.
- Скидка округляется один раз и хранится отрицательным числом.
- `total` равен сумме уже округлённых строк, включая скидку.
- Нельзя считать итог отдельно и получать расхождение с расшифровкой.
- Нельзя хранить цены в HTML, CSS или логике интерфейса.
- Нельзя добавлять скрытые доплаты и ручные скидки.
- В MVP есть только автоматическая скидка за ранний заказ; налогов, доставки, срочной надбавки и промокодов нет.

Функция расчёта должна быть чистой:

```js
window.CakeApp.pricing.calculatePrice(selection, config, today);
// { lines: [...], total: 6400 }
```

`today` — необязательная локальная дата для проверки скидки. Без неё используется текущая дата.

Функция не обращается к DOM и не читает `localStorage`.

## 8. Правила дат

- Использовать локальную дату пользователя, не UTC.
- Минимальная дата: сегодня + `config.leadTimeDays`.
- Максимальная дата: сегодня + `config.maxLeadTimeDays`.
- Время сравнивать в локальном часовом поясе.
- Не использовать `toISOString()` для получения даты пользователя: он переводит в UTC и может дать сдвиг на день.
- Для формата `YYYY-MM-DD` собирать дату вручную из локальных компонентов.
- Выходные и праздники не учитываются.
- Занятость даты не проверяется.
- Просроченная дата из черновика очищается с подсказкой.
- Для скидки считать разницу календарных дней между датой выдачи и сегодняшней локальной датой.
- Сравнивать даты по локальным компонентам, не через UTC-строку.

Пример:

```js
function toLocalISODate(date) {
  const year = date.getFullYear();
  const month = String(date.getMonth() + 1).padStart(2, "0");
  const day = String(date.getDate()).padStart(2, "0");
  return `${year}-${month}-${day}`;
}
```

## 9. Конфиг

`js/config.js` — единственное место, где меняются цены и ограничения.

Правила:

- Не дублировать значения из конфига в других файлах.
- Не хардкодить названия начинок и декора в HTML.
- Все списки начинок и декора генерируются из конфига.
- Экран «Цены» тоже генерируется из конфига.
- Каталог начинок и каталог декора тоже генерируются из конфига.
- При добавлении новой начинки или декора интерфейс должен подхватить её без правок вёрстки.
- У каждой начинки и каждого декора есть уникальный `id`.
- `id` не меняется без необходимости: он используется в черновике.
- Заглушка начинки задаётся только блоком `visual`: поле `style` (`cream`, `chocolate`, `berry`, `caramel`, `nut`) и цвета `from`, `to`, `accent`; изображения из сети не подключаются.
- Иллюстрация декора задаётся блоком `visual`: поле `style` (`none`, `minimal`, `themed`, `figures`) и цвета `from`, `to`, `accent`.
- Если `inscription.enabled` равно `false`, поле надписи скрыто и не влияет на цену.
- Пороги и проценты скидки за ранний заказ задаются только в `earlyBookingDiscount`.
- Если скидка отключена в конфиге, строка скидки не показывается и итог считается без неё.
- Описания должны быть короткими и понятными покупателю.
- Цены — числа без пробелов и символов валюты.
- Валюта форматируется только при выводе.

## 10. Правила кода

### 10.1. Общие

- Классические скрипты, без ES-модулей, чтобы страница открывалась через `file://`.
- Общее пространство имён: `window.CakeApp`.
- Каждый файл инициализирует его безопасно: `window.CakeApp = window.CakeApp || {};`.
- Без глобальных переменных вне `window.CakeApp` и `window.CAKE_CONFIG`.
- Функции — `camelCase`.
- Константы — `UPPER_SNAKE_CASE`.
- CSS-классы — `kebab-case`.
- Идентификаторы — `camelCase`.
- Один файл — одна зона ответственности.
- Никаких inline-обработчиков в HTML.
- Только `addEventListener`.
- Никаких `eval`, `new Function` и динамического исполнения кода.

### 10.2. Безопасность

- Пользовательский текст выводить через `textContent`.
- Не вставлять имя, контакт, комментарий или надпись через `innerHTML`.
- Заглушки каталога строить через `createElementNS`, а не через `innerHTML`.
- Ограничивать длины полей на уровне HTML и JS.
- Не логировать персональные данные в консоль.
- Не хранить API-ключи в клиентском коде.
- Не отправлять данные на сервер в базовом MVP.

### 10.3. localStorage

Ключи:

- `cakeConstructor:draft:v1`
- `cakeConstructor:lastOrder:v1`

Правила:

- Все обращения оборачивать в `try/catch`.
- При ошибке приложение продолжает работать без сохранения.
- Проверять версию данных.
- Не падать, если в хранилище лежит старый или битый JSON.
- Последний заказ хранить как снимок с названиями и ценами на момент заказа.
- Кнопка «Очистить сохранённые данные» удаляет оба ключа.

### 10.4. Форматирование

- Деньги: `Intl.NumberFormat("ru-RU").format(value) + " ₽"`.
- Даты: `Intl.DateTimeFormat("ru-RU")`.
- Не использовать самодельные разделители тысяч.
- Не использовать `toLocaleString()` без указания локали.
- Для русского текста использовать нормальные пробелы и тире.

## 11. Правила интерфейса

### 11.1. Общий подход

- Mobile-first.
- Базовая ширина проверки: 375 px.
- Минимальная ширина: 360 px.
- Одна страница с формой и живым итогом.
- На десктопе форма слева, итог справа.
- На мобильном итог и кнопка закреплены внизу.
- Никаких пошаговых мастеров в MVP.

### 11.2. Сетка и отступы

- Максимальная ширина контента: 1120 px.
- Боковые отступы на мобильном: 16 px.
- Боковые отступы на десктопе: 24–32 px.
- Расстояние между смысловыми блоками: 24–32 px.
- Радиус карточек: 16 px.
- Радиус полей и кнопок: 12 px.
- Липкая панель: не выше 88 px, с учётом `safe-area-inset-bottom`.
- У страницы должен быть нижний отступ, чтобы панель не перекрывала последнее поле.

### 11.3. Цвета

Использовать CSS-переменные:

```css
:root {
  --color-bg: #fff8f0;
  --color-surface: #ffffff;
  --color-text: #2b1b12;
  --color-muted: #7a6a5f;
  --color-accent: #c45a3c;
  --color-accent-dark: #a8472f;
  --color-border: #eadfd5;
  --color-error: #b3261e;
  --color-success: #2e7d5a;
  --radius-card: 16px;
  --radius-control: 12px;
  --shadow-card: 0 8px 24px rgba(43, 27, 18, 0.08);
}
```

- Фон — тёплый кремовый.
- Акцент — терракотовый.
- Текст — тёмно-коричневый.
- Ошибки — тёмно-красный.
- Успех — зелёный.
- Не использовать чистый чёрный и кислотные цвета.

### 11.4. Типографика

- Системный шрифт: `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif`.
- Без внешних шрифтов.
- Основной текст: 16 px.
- Подписи: 14–15 px.
- Заголовок страницы: `clamp(28px, 6vw, 40px)`.
- Итог: 24–32 px.
- Межстрочный интервал: 1,4–1,5.
- Не использовать текст меньше 14 px для значимой информации.

### 11.5. Формы

- Подпись всегда над полем.
- Placeholder не заменяет подпись.
- Поля ввода — не меньше 16 px.
- Высота интерактивных элементов — не меньше 44 px.
- Радиокарточки начинок и декора — крупные, с названием, ценой и описанием.
- Выбранное состояние видно не только по цвету: добавлять рамку, галочку или жирность.
- Контакт: телефон из 11 цифр (первая `7` или `8`) или Telegram username 5–32 символа. Форматирование телефона не влияет на подсчёт цифр.
- Ошибка показывается под полем.
- Ошибка не очищает введённые данные.
- Фокус видимый, с контрастным outline.
- Кнопка «Сформировать заказ» всегда активна.
- При ошибке показывается список ошибок и фокус переходит к первому проблемному полю.

### 11.6. Итог

- Итог обновляется при каждом изменении параметров.
- Без кнопки «Рассчитать».
- Показывать строки: торт, декор, надпись, скидка (если есть), итог.
- Сумма строк должна совпадать с итогом.
- Если надпись пустая, строка надписи не показывается.
- Если скидки нет, строка скидки не показывается.
- Скидку показывать отрицательной суммой и с процентом.
- Если декор «Без декора», показывать `0 ₽` для прозрачности.
- Рядом с итогом — короткое пояснение, что цена предварительная.
- На мобильном липкая панель показывает итог и кнопку.
- Полная расшифровка доступна в блоке итога.

### 11.7. Обратная связь

- После копирования — уведомление «Заказ скопирован. Вставьте его в чат с кондитером».
- Кнопка на 2 секунды меняет подпись на «Скопировано».
- Уведомление не перекрывает кнопку и не мешает повторному копированию.
- Для ошибок использовать встроенные сообщения, а не `alert`.
- Для очистки данных использовать подтверждение в модальном окне, а не `confirm`, если есть время; в крайнем случае допустим `confirm`.

### 11.8. Модальные окна

- Карточка заказа, каталог начинок и экран «Цены» открываются в модальном окне или полноэкранной панели.
- Фокус перемещается внутрь.
- Фокус удерживается внутри.
- Закрытие по `Esc`, кнопке закрытия и клику вне окна.
- После закрытия фокус возвращается на кнопку, которая открыла окно.
- На мобильном окно занимает весь экран.
- Контент окна прокручивается, кнопка копирования остаётся доступной.
- Выбор начинки в каталоге закрывает окно и обновляет форму, итог и черновик.

### 11.9. Адаптивность

- Проверять на 375 px и 1440 px.
- Нет горизонтальной прокрутки.
- Нет обрезанного текста.
- Нет элементов меньше 44 px.
- Липкая панель не перекрывает контент.
- Длинные названия и описания переносятся, а не выходят за границы.
- Таблицы на экране «Цены» на мобильном превращаются в карточки.

### 11.10. Доступность

- Семантические элементы: `main`, `form`, `fieldset`, `legend`, `button`, `dialog`.
- У каждого поля есть `label`.
- Ошибки связаны через `aria-describedby`.
- Итог и статус копирования — `aria-live="polite"`.
- Все элементы доступны с клавиатуры.
- Видимый фокус.
- Контраст не ниже 4,5:1.
- Учитывать `prefers-reduced-motion`.
- Не отключать масштабирование страницы.

## 12. Карточка заказа

Правила:

- Формат — обычный текст с переносами строк.
- Без Markdown-таблиц и HTML.
- В карточке есть имя, контакт, дата и время, способ получения, вес, начинка, декор, надпись, комментарий.
- Если есть скидка, в расшифровке есть строка «Скидка за ранний заказ N%».
- Пустые необязательные строки не выводятся.
- Есть расшифровка и итог.
- Есть предупреждение о предварительной цене.
- Нет внутренних ID.
- Нет персональных данных, кроме имени и контакта, которые ввёл пользователь.
- Сумма в карточке равна итогу на экране.

Копирование:

1. `navigator.clipboard.writeText(text)` при наличии.
2. Иначе скрытый `textarea` и `document.execCommand("copy")`.
3. Иначе модальное окно с текстом и ручным копированием.
4. Успех — уведомление и подпись «Скопировано».
5. Ошибка — понятное сообщение и запасной вариант.

Не отправлять карточку автоматически. Пользователь сам вставляет её в мессенджер.

## 13. AI-описание

AI — опциональная функция. Если она не реализована, не добавлять неработающие кнопки.

Если реализуется:

- Провайдер: GigaChat или YandexGPT.
- API-ключ хранится только на серверном прокси.
- Клиент не содержит ключей.
- В модель передаются только параметры торта: вес, начинка, декор, надпись.
- Имя, контакт и комментарий в модель не передаются.
- Модель не считает цену.
- Модель не придумывает состав, аллергены, сроки и наличие.
- Ответ — 1–2 предложения на русском.
- Текст помечается как «Сгенерировано ИИ».
- При ошибке или таймауте показывается локальное шаблонное описание.
- Ошибка AI не блокирует заказ.
- Цена после генерации не меняется.

Если прокси нет, функцию не включать.

## 14. Definition of Done

Задача считается готовой, когда:

- [ ] Все критерии приёмки из `docs/TZ.md` выполнены.
- [ ] Любое изменение параметров сразу пересчитывает сумму.
- [ ] Расшифровка совпадает с итогом.
- [ ] Некорректный вес блокирует заказ с подсказкой.
- [ ] Прошедшая или слишком ранняя дата блокирует заказ с подсказкой.
- [ ] Пустые имя и контакт блокируют заказ.
- [ ] Телефон не из 11 цифр или с первой цифрой не `7`/`8` блокирует заказ.
- [ ] Произвольный текст и кириллица в контакте блокируют заказ.
- [ ] Надпись длиннее 30 символов блокируется.
- [ ] Скидка 5% применяется за 7–13 дней, 10% — за 14 и более дней.
- [ ] Строка скидки и итог совпадают, последний заказ сохраняет скидку.
- [ ] Карточка копируется одним нажатием.
